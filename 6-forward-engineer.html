Forward engineer: van model naar databank

Ons model is klaar. Met Forward Engineer schrijft Workbench een SQL-script dat de databank op de server aanmaakt, en voert het meteen uit.

De wizard

Forward Engineer is een wizard: een reeks schermen die we met Next doorlopen.

  1. Verbinding kiezen
  2. Opties
  3. Objecten kiezen
  4. Script nakijken
  5. Uitvoeren

  1. Bewaar het model (Ctrl + S). Kies dan Database › Forward Engineer… (Ctrl + G).

  2. Verbinding. Kies bij Stored Connection onze verbinding, bijvoorbeeld Local instance MySQL80. Klik op Next en geef het wachtwoord in als Workbench erom vraagt.

  3. Opties. De eerste keer laten we alle vakjes uit. Klik op Next. Verderop lezen we wanneer we hier toch iets aanvinken.

  4. Objecten. Het vakje Export MySQL Table Objects staat aan. Er staan 7 tabellen klaar. Klik op Next.

  5. Script nakijken. Workbench toont het SQL-script dat het zal uitvoeren. Lees het even (zie hieronder). Met Save to File… kunnen we het bewaren, bijvoorbeeld als festival_create.sql. Klik op Next.

  6. Uitvoeren. Workbench voert het script uit en toont groene vinkjes. Klik op Close. Zien we een rood kruisje, lees dan de melding en kijk in de tabel onderaan deze pagina.

Wat staat er in het script?

Workbench vertaalt elke tabel uit ons model naar een CREATE TABLE-opdracht. Zo ziet die van artiest eruit:

CREATE SCHEMA IF NOT EXISTS `festival` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci ;
USE `festival` ;

CREATE TABLE IF NOT EXISTS `festival`.`artiest` (
  `artiestID` INT NOT NULL AUTO_INCREMENT,
  `naam` VARCHAR(60) NOT NULL,
  `land` VARCHAR(45) NOT NULL,
  `genreID` INT NOT NULL,
  PRIMARY KEY (`artiestID`),
  INDEX `fk_artiest_genre_idx` (`genreID` ASC) VISIBLE,
  CONSTRAINT `fk_artiest_genre`
    FOREIGN KEY (`genreID`)
    REFERENCES `festival`.`genre` (`genreID`)
    ON DELETE NO ACTION
    ON UPDATE NO ACTION)
ENGINE = InnoDB;
RegelWat doet ze?
CREATE SCHEMA IF NOT EXISTSMaakt de databank festival, tenzij die al bestaat.
NOT NULL AUTO_INCREMENTOnze vinkjes NN en AI.
PRIMARY KEY (`artiestID`)Het vinkje PK.
INDEX `fk_artiest_genre_idx`Een index: een soort register waarmee de server snel opzoekt welke artiesten bij een genre horen. MySQL wil een index op elke RS; Workbench maakt die automatisch.
CONSTRAINT … FOREIGN KEY … REFERENCESDe beperking die de referentiële integriteit bewaakt: genreID moet bestaan in genre.
ON DELETE NO ACTIONWat er gebeurt als we een genre verwijderen dat nog gebruikt wordt. Daarover gaat stap 8.
ENGINE = InnoDBDe opslagmanier van MySQL die refererende sleutels ondersteunt.

Bovenaan en onderaan het script staan nog enkele regels SET @OLD_…. Die zetten tijdelijk een paar controles uit, zodat de tabellen in eender welke volgorde aangemaakt kunnen worden.

Het volledige script van ons voorbeeld vind je hier: festival_create.sql. Gebruik het om te vergelijken.

De databank controleren

  1. Ga naar het startscherm (het huisje linksboven) en open de verbinding.

  2. Klik in de Navigator bij Schemas op het icoon met de twee pijltjes (vernieuwen), of klik rechts in de lijst en kies Refresh All. De databank festival verschijnt.

  3. Klap festival en daarna Tables open. We zien zeven tabellen.

  4. We kunnen het ook met SQL nakijken. Open een query-tab (Ctrl + T), typ deze opdrachten en voer ze uit met Ctrl + Shift + Enter:

SHOW TABLES FROM festival;
DESCRIBE festival.artiest;

DESCRIBE toont de structuur van een tabel. Voor artiest krijgen we:

FieldTypeNullKeyDefaultExtra
artiestIDintNOPRINULLauto_increment
naamvarchar(60)NONULL
landvarchar(45)NONULL
genreIDintNOMULNULL

PRI staat voor primaire sleutel. MUL betekent dat er een index op de kolom staat waarin dezelfde waarde meerdere keren mag voorkomen: zo herkennen we een RS.

Model aangepast? Opnieuw naar de server

Het script gebruikt CREATE TABLE IF NOT EXISTS. Bestaat een tabel al, dan slaat de server ze over. Een wijziging in ons model komt dus niet door als we Forward Engineer gewoon opnieuw uitvoeren. We hebben twee mogelijkheden:

MethodeHoe?Gevolg
Alles opnieuw (eenvoudig)Forward Engineer opnieuw, en bij Opties Generate DROP Statements Before Each CREATE Statement en Generate DROP SCHEMA aanvinken.De databank wordt verwijderd en opnieuw gemaakt. Alle gegevens zijn weg: voer daarna het insert-script uit stap 7 opnieuw uit.
SynchroniserenDatabase › Synchronize Model… (Ctrl + Y). Workbench vergelijkt model en databank en toont welke wijzigingen het zal doorvoeren.Enkel de verschillen worden aangepast; de gegevens blijven zoveel mogelijk behouden.

Let op met DROP

DROP SCHEMA verwijdert de volledige databank met alle gegevens, zonder te vragen of we het zeker weten. Gebruik het enkel als we alle gegevens opnieuw kunnen invoeren met een script.
