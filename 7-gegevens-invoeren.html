Gegevens invoeren met INSERT INTO

Een lege databank is niet erg nuttig. We schrijven een SQL-script dat de tabellen vult met testgegevens. Zo'n script bewaren we, zodat we het altijd opnieuw kunnen uitvoeren.

Een query-tab openen

  1. Open de verbinding vanuit het startscherm van Workbench.

  2. Kies File › New Query Tab (Ctrl + T).

  3. Laat het script beginnen met USE festival;. Zo weet de server in welke databank de tabellen staan. (Dubbelklikken op festival in de Navigator doet hetzelfde: de naam wordt dan vet.)

  4. Bewaar het script meteen: File › Save Script As… als festival_insert.sql in je map Databeheer.

De opbouw van INSERT INTO

Eén rij toevoegen aan de tabel genre:

INSERT INTO genre (genreID, naam)
VALUES (1, 'Pop');
  • Na INSERT INTO komt de naam van de tabel.
  • Tussen haakjes volgen de kolommen die we invullen.
  • Na VALUES volgen de waarden, in dezelfde volgorde als de kolommen.
  • Elke opdracht eindigt met een puntkomma ;.

Meerdere rijen tegelijk? Zet ze achter elkaar, gescheiden door komma's:

INSERT INTO genre (genreID, naam) VALUES
(1, 'Pop'),
(2, 'Rock'),
(3, 'Hiphop');

NULL of 'NULL'?

NULL betekent: geen waarde. 'NULL' tussen aanhalingstekens is gewoon een tekst van vier letters. In een kolom van het type INT geeft dat een fout.

AUTO_INCREMENT: zelf een ID geven of niet?

Omdat de PS-kolommen AUTO_INCREMENT hebben, mogen we het ID weglaten. De server kiest dan zelf het volgende nummer:

INSERT INTO podium (naam, capaciteit, overdekt)
VALUES ('Silent Disco', 800, 1);

In een testscript geven we de ID's meestal wél zelf. Dan weten we zeker dat genre 4 'Dance' is, en kunnen we in de tabel artiest naar genreID 4 verwijzen. Lukt een INSERT niet, dan kan de server een nummer overslaan. Zo'n gat in de nummering is normaal.

Laten we een kolom met een standaardwaarde weg, dan vult de server die in. Bij podium wordt overdekt dan 0.

De volgorde: eerst ouders, dan kinderen

In artiest staat de RS genreID. De server aanvaardt een artiest met genreID 4 enkel als genre 4 al bestaat. Daarom vullen we de tabellen in deze volgorde:

  1. Tabellen zonder RS: genre, podium, campingzone.

  2. Tabellen die naar die ouders verwijzen: artiest (naar genre) en bezoeker (naar campingzone).

  3. Koppeltabellen: optreden (naar artiest en podium) en favoriet (naar bezoeker en artiest).

Kijk in het EER-diagram: een tabel komt pas aan de beurt als alle tabellen aan de één-kant van haar relaties al gevuld zijn.

Uitvoeren en controleren

  1. Voer het hele script uit met het bliksem-icoon of met Ctrl + Shift + Enter. Eén opdracht uitvoeren (die waar de cursor in staat) gaat met Ctrl + Enter.

  2. Bekijk onderaan het paneel Output. Per opdracht staat er een regel met een groen vinkje en het aantal toegevoegde rijen.

  3. De laatste opdracht van het script telt de rijen per tabel. Verwacht: 6, 4, 3, 12, 15, 16 en 30.

  4. Bekijk de gegevens van een tabel: klik in de Navigator met de rechtermuisknop op de tabel en kies Select Rows - Limit 1000, of typ SELECT * FROM artiest;

Opnieuw beginnen

Liep het script half mis en willen we het opnieuw uitvoeren? Dan geven de rijen die al bestaan fout 1062. Tijdens het testen zetten we daarom dit blok bovenaan het script. Het maakt alle tabellen leeg en zet de nummering terug op 1.

-- Alle tabellen leegmaken (enkel tijdens het testen!)
SET FOREIGN_KEY_CHECKS = 0;
TRUNCATE TABLE favoriet;
TRUNCATE TABLE optreden;
TRUNCATE TABLE bezoeker;
TRUNCATE TABLE artiest;
TRUNCATE TABLE campingzone;
TRUNCATE TABLE podium;
TRUNCATE TABLE genre;
SET FOREIGN_KEY_CHECKS = 1;

Let op

SET FOREIGN_KEY_CHECKS = 0 zet de controle op refererende sleutels tijdelijk uit, zodat we de tabellen in eender welke volgorde kunnen leegmaken. Zet ze altijd meteen terug aan met = 1.

Zelf aan de slag

  1. Voeg jezelf toe als bezoeker, zonder een bezoekerID op te geven. Je kampeert in zone Rustig.
  2. Duid drie artiesten aan als jouw favoriet. Zoek eerst op welk bezoekerID je kreeg.
  3. Voeg het genre Reggae toe, een artiest uit dat genre en een optreden van die artiest op zondag in Het Bos.
  4. Probeer bewust een fout: een optreden voor artiest 99. Welke foutcode krijg je, en waarom?
Toon een mogelijke oplossing 
-- 1. Jezelf toevoegen (zone Rustig = campingzoneID 2)
INSERT INTO bezoeker (voornaam, familienaam, email, geboortedatum, campingzoneID)
VALUES ('Sam', 'Peeters', 'sam.peeters@example.com', '2008-06-01', 2);

-- 2. Welk ID kreeg ik?
SELECT bezoekerID FROM bezoeker WHERE email = 'sam.peeters@example.com';
-- stel dat het 16 is:
INSERT INTO favoriet (bezoekerID, artiestID) VALUES (16, 1), (16, 5), (16, 9);

-- 3. Reggae, een artiest en een optreden
INSERT INTO genre (naam) VALUES ('Reggae');            -- krijgt genreID 7
INSERT INTO artiest (naam, land, genreID) VALUES ('Island Breeze', 'Jamaica', 7);  -- artiestID 13
INSERT INTO optreden (datum, beginuur, einduur, artiestID, podiumID)
VALUES ('2027-07-11', '13:00:00', '14:00:00', 13, 4);

-- 4. Bewuste fout: artiest 99 bestaat niet
INSERT INTO optreden (datum, beginuur, einduur, artiestID, podiumID)
VALUES ('2027-07-11', '15:00:00', '16:00:00', 99, 1);
-- Error Code: 1452. Cannot add or update a child row: a foreign key constraint fails

De nummers 16, 7 en 13 kloppen enkel als je het festivalscript precies één keer foutloos uitvoerde. Kijk ze dus altijd na met SELECT.
