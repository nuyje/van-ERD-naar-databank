Stap 8 van 8

Referentiële integriteit testen

Refererende sleutels bewaken de samenhang van onze gegevens: de server weigert gegevens die naar het niets verwijzen. In deze stap testen we dat, en bepalen we wat er moet gebeuren als we een rij verwijderen waar andere rijen naar verwijzen.

Wat is referentiële integriteit?

Elke waarde in een refererende sleutel moet bestaan als primaire sleutel in de tabel waarnaar ze verwijst, of leeg zijn als dat toegelaten is. Heeft een artiest genreID 4, dan moet genre 4 bestaan. De server controleert dat bij elke INSERT, UPDATE en DELETE.

Gebruik voor de testen hieronder de databank uit stap 7, gevuld met festival_insert.sql. Voer elke opdracht apart uit met Ctrl + Enter.

Test 1: een kind zonder ouder

USE festival;

INSERT INTO optreden (datum, beginuur, einduur, artiestID, podiumID)
VALUES ('2027-07-11', '15:00:00', '16:00:00', 99, 1);

Resultaat: Error Code: 1452. Cannot add or update a child row: a foreign key constraint fails. Er bestaat geen artiest 99, dus de server weigert het optreden.

Test 2: een ouder met kinderen verwijderen

DELETE FROM genre WHERE genreID = 1;

Resultaat: Error Code: 1451. Cannot delete or update a parent row: a foreign key constraint fails. Genre 1 (Pop) heeft artiesten. Mocht de server het genre toch verwijderen, dan verwezen die artiesten naar een genre dat niet meer bestaat. Zonder genre-artiesten lukt het wel: genre 6 (Metal) kunnen we gewoon verwijderen.

ON DELETE en ON UPDATE

Bij elke refererende sleutel bepalen we wat de server doet als de ouder verwijderd (ON DELETE) of de PS van de ouder gewijzigd (ON UPDATE) wordt.

OptieWat gebeurt er met de kinderen?
RESTRICT of NO ACTIONNiets: de server weigert de ouder te verwijderen zolang er kinderen zijn. Dit is de standaard in Workbench. In MySQL betekenen beide hetzelfde.
CASCADEDe kinderen worden mee verwijderd (bij ON DELETE) of hun RS wordt mee aangepast (bij ON UPDATE). Dit heet cascading delete en cascading update.
SET NULLDe RS van de kinderen wordt leeg. Kan enkel als die RS leeg mag zijn.

Het model aanpassen

  1. Open festival.mwb en het EER-diagram.

  2. Dubbelklik op de tabel favoriet en open in de tabeleditor het tabblad Foreign Keys.

  3. Selecteer links de RS die naar bezoeker verwijst. Kies rechts bij Foreign Key Options voor On Delete de waarde CASCADE.

  4. Doe hetzelfde voor de RS die naar artiest verwijst.

  5. Dubbelklik op bezoeker, open Foreign Keys, selecteer de RS naar campingzone en kies bij On Delete de waarde SET NULL.

  6. Bewaar het model.

De wijziging naar de databank brengen

Zoals we in stap 6 zagen, komt een wijziging niet door met een gewone Forward Engineer. Kies een van de twee methodes:

  • Alles opnieuw: Forward Engineer met Generate DROP Statements Before Each CREATE Statement en Generate DROP SCHEMA aangevinkt. Voer daarna festival_insert.sql opnieuw uit.
  • Synchroniseren: Database › Synchronize Model… Workbench toont de ALTER TABLE-opdrachten die het zal uitvoeren. De gegevens blijven staan.

Test 3: CASCADE

Kid Kompas (artiest 12) heeft zijn optredens geannuleerd, maar staat nog bij drie bezoekers als favoriet.

SELECT * FROM favoriet WHERE artiestID = 12;   -- 3 rijen

DELETE FROM artiest WHERE artiestID = 12;

SELECT * FROM favoriet WHERE artiestID = 12;   -- 0 rijen

De artiest is verwijderd, en zijn drie favorieten zijn automatisch mee verdwenen.

Test 4: SET NULL

DELETE FROM campingzone WHERE campingzoneID = 3;

SELECT voornaam, familienaam, campingzoneID
FROM bezoeker
WHERE bezoekerID IN (7, 11, 15);

Zone Comfort is weg. Nora, Amélie en Elena bestaan nog, maar hun campingzoneID is nu NULL.

Test 5: RESTRICT blijft werken

DELETE FROM artiest WHERE artiestID = 1;

Neon Atlas heeft twee optredens. De RS in optreden staat op RESTRICT, dus de server weigert met fout 1451.

Denkvraag: waarom lukt Kid Kompas wel en Neon Atlas niet?

Beide artiesten staan in favoriet, en daar mag de server cascaderen. Maar Neon Atlas staat ook in optreden, en die RS staat op RESTRICT. Eén weigerende relatie volstaat om het verwijderen te blokkeren. Kid Kompas heeft geen optredens, dus niets houdt hem tegen.

Extra: van databank naar model

Met Database › Reverse Engineer… (Ctrl + R) maakt Workbench een model en EER-diagram van een bestaande databank. Handig om de databank van iemand anders te bekijken, of als je je .mwb-bestand kwijt bent.
